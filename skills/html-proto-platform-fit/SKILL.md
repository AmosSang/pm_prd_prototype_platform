# HTML 原型适配产品方案展示平台

## 目的
平台把原型放进沙箱 iframe 并注入桥接脚本，承担锚点上报、反向定位、评论采集、截图，以及「文档定位 → 自动打开弹窗/Tab/折叠区 → 滚动到元素」的揭示流水线。揭示流水线靠 `aria-controls` 关联和常驻 DOM 工作。本技能给出让这些能力可用的结构约束（新做）与改造流程（已有）。只做结构适配，不改视觉、不改交互含义、不删功能、不加 `data-pa`。

## 硬性规则
1. **静态优先**：页面骨架和核心内容直接写在 HTML 里（平台锚点对账是服务端静态解析，JS 运行时才出现的元素它看不到）；JS 只做数据填充和交互反馈。
2. **常驻 DOM**：弹窗/抽屉/Tab/浮层/折叠区内容常驻 DOM，关闭只切 `hidden` 或 class；禁止 `remove()` 后重建。
3. **标准关联**：每个开合控件写 `aria-controls="目标容器id"`（Tab 另加 `role`/`aria-selected`，弹窗加 `aria-expanded`）；目标容器必须有稳定 `id`；折叠区优先用原生 `<details>/<summary>`。
4. **真实触发器**：控件的 onclick 必须真实切换目标容器显隐。禁止 `return false` 伪触发器、只弹 toast 不改 DOM 的按钮——程序化点击时它们静默失败，人工点击却看不出来。
5. **隐藏只用标准形态**：`hidden` 属性 / `display:none` / 未展开 `<details>`。禁止 `opacity:0`、`left:-9999px` 等非常规隐藏（可见性判定可能误判）。
6. **页面形态**：多页原型（每页独立 .html + `<a href>`，zip 根顶层要有一个 .html）或单文件 SPA 假页（`.screen` 显隐切换）均可；SPA 每个假页必须有至少一个真实入口控件。
7. **禁止**：`document.write`（会销毁注入的桥接脚本）、`window.open` 承载核心流程（平台消息链路够不到新窗口）、虚拟列表/懒渲染承载核心内容（锚点间歇性不在 DOM）。
8. **JS 内按锚点属性查询**写不带引号选择器（`[data-pa=xxx]`），避免后续对账误报——现在养成习惯即可，本阶段不打锚。

## 已知坑（改造时重点排查）
- `querySelector` 误选中：同名 class 有多份时 `querySelector` 永远拿第一个，切换显隐会操作错对象；用 id 或 `:not()` 精确化。
- JS 模板串拼 HTML 时引号嵌套冲突（`onclick="..." aria-controls="..."` 与外层属性双引号），生成坏 HTML；属性值改用单引号或把 aria 属性放 onclick 之外。
- 「点外部关闭浮层」的全局 click 监听会与平台评论模式点击互相干扰，可接受但要知道存在。

## 场景一：新做原型
按硬性规则生成，交付前自检：
- [ ] 每个 .html 独立打开，控制台零报错（原型自身脚本报错会连带桥接脚本失效）
- [ ] 弹层/Tab 内容常驻 DOM；开合控件有 `aria-controls` + 容器有 id；handler 真实驱动显隐
- [ ] 无 `document.write`、`window.open` 核心流程、虚拟列表、非常规隐藏

## 场景二：改造已有原型
按顺序审计并修复：
1. 全局扫描：`document.write`、`window.open`、虚拟列表迹象 → 有则改。
2. 隐藏形态审计：确认弹层/Tab/抽屉常驻 DOM、只切显隐；销毁重建 → 改常驻；非常规隐藏 → 改标准隐藏。
3. 触发器关联审计：逐个开合容器——无 id 补 id；找到负责打开它的控件补 `aria-controls`；折叠区改 `<details>`；验证 handler 真实性，伪触发器接上真实显隐逻辑。
4. SPA 假页审计：每个假页有真实入口控件，切换函数真实驱动显隐。
5. JS 修复：querySelector 误选、模板引号嵌套、锚点查询去引号。
6. 浏览器实测（不可省）：无头浏览器加载原型，对每个开合容器执行 `querySelector('[aria-controls=id]').click()` 后断言容器可见。静态审计看不出伪触发器、运行时报错、选择器误选——真实案例：改造 2100 行 SPA 原型时靠这一步挖出 3 个静态检查漏掉的 bug。
7. 控制台零报错确认。

## 与 prd-html-anchor 的衔接
本技能完成后，原型结构已就绪；打 `data-pa` 锚点与 PRD 配对、对账检查由 `prd-html-anchor` 技能负责，届时再做。
