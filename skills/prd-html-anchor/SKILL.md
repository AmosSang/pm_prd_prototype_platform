# PRD ↔ HTML 原型双向锚点关联

## 目的
为 PRD(md) 与 HTML 原型的关键元素建立可跳转的定位关系，供外部读取程序在两者间互相定位。只加标记，不改功能、样式或文案含义。

## 何时使用
- 用户要求给 PRD 与 HTML 原型"加锚点 / 互相关联 / 互相跳转 / 双向定位"（**场景一：新建**）。
- 用户大幅修改了 PRD 或原型（改版、重写、重构），要求"检查锚点 / 修复锚点 / 补锚点 / 重新配对 / 清理失效锚点"（**场景二：复查完善**）。
- 用户提到给关键元素打标记，且涉及 md 与 html 两套文件。

## 核心规则
1. HTML 关键元素加 `data-pa="ID"`。静态标签直接写属性；JS 运行时动态创建的元素用 `el.setAttribute('data-pa','ID')`。
2. PRD(md) 中，在描述该元素的标题或段落**同一行行尾**加 `<!-- pa: ID -->`。
3. 两侧 ID 必须字对字一致（大小写、连字符均一致）；一侧有、另一侧缺即为孤儿，会导致断链。

## 锚点 ID 命名
采用 `页面前缀 + 元素语义`，全局跨页面唯一。
- 前缀按页面取，例如 `auth-` / `index-` / `edit-` / `stroll-`（按实际页面调整）。
- 语义用小写英文短词，仅用 `[a-z0-9-]`，禁用空格、中文、特殊符号。
- 例：`auth-login`、`index-calendar`、`edit-content`、`stroll-next`、`stroll-detail-link`。

## 哪些元素要打锚点
只打 PRD 有重点描述交互、表单或业务逻辑的元素：表单与字段、带逻辑的按钮、数据/状态展示区、导航跳转入口。纯装饰元素不打。

## 放置铁律（最易错）
PRD 的 `<!-- pa: -->` 必须贴在"它要锚定的那行内容"的**同一行末尾**，**不要单独成行**——否则读取程序会锚到空注释行，跳转失准。
- 整段级锚点 → 贴在对应标题行尾。
- 字段级锚点 → 贴在描述该字段的段落行尾。
- 同一行可串联多个锚点：`...<!-- pa: a --><!-- pa: b -->`。

## 场景一：新建锚点（从零）

适用于全新的 PRD 与原型，或从未打过锚点的项目。

1. 通读 PRD，圈出有重点交互 / 表单 / 逻辑的功能点，作为锚点候选。
2. 为每个候选起一个 `前缀-语义` 的 ID。
3. 在 HTML 对应元素上加 `data-pa`（动态生成的元素用 `setAttribute` 注入）。
4. 在 PRD 对应标题 / 段落的**同行末尾**加 `<!-- pa: ID -->`。
5. 自检：跑检查脚本（见下节），全部通过后交付。

## 场景二：复查与完善（改版后）

适用于已打过锚点、之后 PRD 或原型经过大幅修改（改版/重写/重构/删功能）的项目。大幅修改常导致三类锚点损伤：**锚点漂移**（段落改写后锚点注释被删/被移/落在空行）、**配对断裂**（一侧保留旧锚点、另一侧元素已删除）、**新增内容无锚点**（新功能描述/新控件没打标）。流程：

1. **先跑检查脚本拿现状**（不要凭肉眼从零找）：

   ```bash
   python <本技能目录>/check_orphan_anchors.py <项目目录>
   ```

   脚本会列出全部问题并附修复建议（补哪侧 / 删一侧 / 改 ID / 移回行尾）。

2. **逐类处置脚本报出的问题**：
   - **孤儿锚点（PRD 有 / 原型缺）**：先判断对应功能是否还存在。功能还在 → 在原型侧按 ID 语义找到新位置的元素补 `data-pa`；功能已删 → 删掉 PRD 侧该锚点注释，不留死链。
   - **孤儿锚点（原型有 / PRD 缺）**：同理反向处理。注意大幅重写 PRD 后段落措辞变了，锚点注释可能整段丢失——按原型侧锚点 ID 语义在 PRD 中找新段落补注释。
   - **重复 ID**：改版后两个不同内容撞了同一个旧 ID。逐处核对语义，保留正确的一处；另一处若描述的是新功能，起新 ID 而不是复用旧 ID。
   - **单独成行**：改版重排导致锚点脱离内容行。移回目标标题/段落行尾；若锚定内容已删，直接删除注释。
   - **命名违规**：两侧同步改为合法 ID。
3. **补新增内容的锚点**：按「哪些元素要打锚点」的标准，把改版新增的功能描述（PRD）与新控件（原型）按场景一的规则补齐锚点——这是脚本检不出来的，需要通读新旧版本对照。
4. **复跑脚本验证**：全部通过（exit 0）才算复查完成。
5. **不确定就问**：拿不准某锚点该补还是该删（即功能是否保留）时，向用户确认，不要擅自决定。

**删除纪律**：删锚点必须两侧一起删（一侧的 `data-pa` + 另一侧的 `<!-- pa: -->`）。只删一侧等于制造新孤儿。

## 自检脚本 check_orphan_anchors.py
零依赖（仅 Python 标准库），检查孤儿锚点、重复 ID、单独成行、命名违规四类问题，**每个问题附修复建议**（新建后自检与改版后复查都用它）：

```bash
# 项目目录形态（下含 prd/ 与 prototype/，与平台项目目录约定同构）
python <本技能目录>/check_orphan_anchors.py <项目目录>

# 显式指定路径形态（单文件或目录均可）
python <本技能目录>/check_orphan_anchors.py --prd <md路径> --proto <原型路径>
```

- 检查项：PRD 有原型缺 / 原型有 PRD 缺的孤儿、PRD 或原型侧重复 ID、PRD 中锚点单独成行、ID 命名违规（非 `[a-z0-9-]`）。
- 每类问题附修复建议：孤儿给出「补对侧或两侧删」判断提示，重复给出「保一处、其余改新 ID」指引，单独成行给出「移回行尾或删除」指引。
- 原型侧同时识别静态 `data-pa` 属性与 JS `setAttribute('data-pa', …)` 动态注入，按行扫描源码，不需要跑浏览器。
- 退出码：`0` 全部通过；`1` 有问题（明细列出位置与建议）；`2` 参数/路径错误——可直接用于 CI 门禁。
- 可选 `--json`（机器可读输出，含 suggest 字段）、`--quiet`（仅一行汇总）。

## 最小示例
HTML:
`<button id="logout" data-pa="index-logout">登出</button>`

PRD:
`**6.1.4 登出（P0）**<!-- pa: index-logout -->`
`- 必填：正文（非空，1–5000 字）。<!-- pa: edit-content -->`
